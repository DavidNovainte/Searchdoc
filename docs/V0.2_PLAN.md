# SearchDoc v0.2：可靠性计划

目标：让 SearchDoc 在日常使用中“搜得到、同步不丢数据、失败可解释、重启可恢复”，具备发布给自己长期使用的稳定性。

## 版本边界

v0.2 暂不新增 Notion、网页搜索、RAG 或多用户权限。优先稳定现有两类来源：本地文件和 Google Docs。

## 里程碑

### M1：同步状态与错误体验

- [ ] 统一同步状态：空闲、准备、扫描、索引、完成、取消、失败
- [ ] 显示来源级进度：已发现、已处理、已更新、未变化、失败
- [ ] 统一错误分类：权限、网络、文件读取、解析、数据库
- [ ] 同步结束后保留摘要，不用模糊的“同步完成”覆盖细节
- [ ] 取消同步后，前端和后端都回到可继续操作状态
- [ ] 防止 UI 同步、托盘同步和启动同步互相覆盖状态

验收：手动取消本地大目录同步、断网同步、Google 权限失效同步，都能看到明确结果；再次同步不需要重启应用。

### M2：索引数据安全

- [ ] 同步前确认删除策略，禁止空扫描结果导致误删已有索引
- [ ] 记录每个来源的最后成功同步时间和最后错误
- [ ] 增加数据库备份/恢复入口
- [ ] 数据库打开失败时保留原文件并生成可恢复副本
- [ ] 为 schema migration 增加测试
- [ ] 检查 Google watchlist、OAuth 配置和索引数据库的路径迁移行为

验收：模拟读取失败、权限失败、数据库升级和应用强制退出后，已有索引仍可搜索，且能恢复。

### M3：搜索质量回归

- [ ] 建立固定 fixture：中文、英文、中英混合、标题、正文、重复文档、空文档
- [ ] 覆盖 fuzzy、exact、title、body、OR、NOT、mtime 排序
- [ ] 覆盖本地与 Google 来源过滤
- [ ] 覆盖重复同步不重复写入
- [ ] 覆盖删除文件后的索引清理
- [ ] 记录 1k、10k 文档规模下的搜索耗时

验收：核心搜索场景有自动化测试；同一查询在重启前后结果一致；普通搜索在本地 fixture 上保持即时响应。

### M4：发布与维护基础

- [ ] 添加 LICENSE
- [x] 添加 CI：TypeScript 构建、Rust fmt、Clippy、Rust test
- [ ] 增加 Windows 干净环境安装测试清单
- [x] 更新 README、ARCHITECTURE 和 Google 配置文档，去掉过时的 sample 描述
- [ ] 明确版本号、安装包产物和升级注意事项
- [ ] 给常见 Google OAuth 错误补充用户可执行的排查提示

验收：从干净环境安装后，可以不依赖仓库目录运行；文档能让新用户完成本地搜索和 Google 连接。

## 推荐实现顺序

1. 先做 M1，建立同步状态模型和用户可见反馈。
2. 再做 M2，确保任何同步失败都不会伤害已有数据。
3. 用 M3 把已有搜索能力固定下来，避免后续重构倒退。
4. 最后做 M4，准备内部发布或首个稳定安装包。

## 暂缓事项

- 新数据源
- 向量搜索和 RAG
- 全盘文件名秒搜
- 多用户、团队权限和云端索引
- 大规模前端重构

## v0.2 完成定义

以下条件全部满足才算完成：

1. 同步过程可观察、可取消、可重试。
2. 同步失败不会删除或污染已有索引。
3. 核心搜索行为有自动化回归测试。
4. 数据库和配置有基本恢复路径。
5. 能从干净 Windows 环境安装并完成首次使用。
